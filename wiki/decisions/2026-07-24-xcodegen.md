# 2026-07-24 — XcodeGen 项目配置管理

> 最后更新：2026-07-24

## 背景

iOS 工程传统使用 `.xcodeproj` 文件管理项目配置，在多人协作时极易产生 git 合并冲突，且包含本地绝对路径，不利于 CI 构建。

## 决策

使用 XcodeGen 管理 iOS 工程配置。项目结构通过 `project.yml` 声明式定义，`.xcodeproj` 由 `xcodegen generate` 命令从 YAML 生成，不提交到仓库。同时使用 xcconfig 文件分离 Debug/Release 环境配置。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| XcodeGen + project.yml | YAML 可读性好；git 友好；支持 xcconfig；CI 易集成 | 需额外安装工具 | 采纳 |
| Tuist | 原生 Swift DSL | 学习成本高；社区相对较小 | 拒绝（过度工程） |
| 直接提交 .xcodeproj | 无需额外工具 | git 冲突频繁；CI 不友好 | 拒绝 |

## 影响

- `.xcodeproj` 加入 `.gitignore`，不提交到仓库
- `project.yml` 声明 target、sources、build settings
- `xcconfig` 分离 Debug/Release 环境配置
- CI 中 iOS job 的第一步为 `xcodegen generate`

### 源文件

- `ios/project.yml` — XcodeGen 项目配置
- `ios/Configs/Debug.xcconfig` — Debug 环境配置
- `ios/Configs/Release.xcconfig` — Release 环境配置
