# 查阅流程

## 何时查阅

在以下时机，**必须先查阅 llm-wiki** 再继续工作：

- 新需求启动，需要理解相关功能的现有逻辑
- 技术方案设计，需要了解相关模块的现有实现方式
- 用户询问「XX 功能怎么做」「XX 是怎么实现的」等
- 修改某功能前，需要了解其完整上下文

## 查阅流程

1. **定位** — 从 `wiki/index.md` 找到目标功能文档
2. **读取** — 完整阅读相关文档（含子文档），理解现有逻辑
3. **定位代码** — 依文档中的文件路径指引定位到关键源文件
4. **验证** — 对比文档描述与代码实际状态是否一致
5. **反馈** — 如发现不一致，以代码为准，通过 generate-and-update subagent 增量更新 wiki（不直接在主会话中修改 wiki 文件）

## 查阅原则

- **先看 wiki 再看代码**：wiki 是代码的结构化索引，能让你更快定位
- **不信任过时信息**：如果 wiki 描述与代码不符，以代码为准并立即更新 wiki
- **关联查阅**：一个功能可能依赖其他功能，顺着文档中的依赖关系关联查阅

## 工作示例

```
用户：「我要做播放器的倍速功能，帮我看看现在播放器怎么实现的」

Agent 执行：
1. 读 wiki/index.md → 定位到 features/video-player/
2. 读 wiki/features/video-player/index.md → 理解播放器现有架构
3. 读文档中标注的源文件路径 → 验证实现与文档一致
4. 读 wiki/api/player.md → 了解现有 API 接口
5. 向用户汇报现有播放器的实现方式，作为新功能的设计基础
```
