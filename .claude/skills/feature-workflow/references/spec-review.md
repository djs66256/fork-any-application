# 需求 Review Subagent

spec-review 阶段的执行者是一个 subagent。它读取需求文档，按审查维度逐项检查，发现问题直接修复，无法修复的上报给人工。

## 使用方式

1. spec-writing 阶段完成后，主 agent 派发 spec-review subagent
2. subagent 自行加载 skill、读取 spec.md 和相关 wiki 文档
3. subagent 按审查维度检查并修复
4. subagent 完成后，主 agent 检查 spec-review.md 中是否有遗留问题
5. 如有遗留问题，暂停并询问用户；如无，调用 `workflow.py advance` 推进到 spec-human-review

## Subagent 定义

```
Subagent：
  description: "Review：需求文档-<feature-name>"
  prompt: |
    你是一个需求文档质量审查 agent。

    ## 准备

    1. 通过 Skill 工具加载 `feature-workflow` skill，指定阶段：`spec-review`，获取模板和规范上下文。
    2. 读取需求文档 `docs/specs/<YYYY-MM-dd>-<name>/spec.md`。
    3. 通过 Skill 工具加载 `llm-wiki` skill，读取相关 wiki 文档作为参考。

    ## 阶段 1：Clarify（清洗模糊点）

    先扫描 spec.md 中所有 `[待确认]` 标记，逐一解决：

    - 能从 wiki 中确认的 → 直接修改并移除标记
    - 能从代码中确认的 → 读取代码确认后修改并移除标记
    - 需要产品决策的 → 保留标记，记录到遗留问题
    - 不影响推进的 → 给出合理默认值，标注"默认采用：..."

    所有 `[待确认]` 标记处理完成后，进入审查。

    ## 阶段 2：审查维度

    ### 1. 完整性

    检查以下内容是否都已充分描述：

    - [ ] 需求背景：是否清晰说明了"为什么做"和"要解决什么问题"
    - [ ] 用户故事：是否覆盖了所有角色和场景
    - [ ] 验收标准：是否可度量、可测试，没有模糊表述
    - [ ] 边界与异常：是否考虑了网络异常、数据为空、操作失败等场景
    - [ ] 涉及平台：是否明确了各端的改动范围
    - [ ] 非功能性需求：是否考虑了性能、安全、兼容性
    - [ ] 依赖：是否列出了外部依赖及其状态

    ### 2. 一致性（与 wiki 和代码）

    将需求描述与 wiki 中已有功能文档进行交叉比对：

    - [ ] 需求描述是否与 wiki 中已有功能逻辑冲突
    - [ ] 如涉及已有功能变更，是否说明了变更范围和影响
    - [ ] 术语和概念是否与项目已有定义一致
    - [ ] API 路径、数据模型等是否与现有设计一致

    ### 3. 可行性

    - [ ] 需求是否有明显的技术上不可行之处
    - [ ] 是否依赖尚未实现的基础能力
    - [ ] 各端改动估算是否合理

    ### 4. 平台覆盖

    - [ ] 涉及平台的标注是否准确
    - [ ] 各端需求是否有遗漏

    ## 修复流程

    发现问题后**直接修正 spec.md**，不要等主 agent 指出：

    - 描述不清 → 补充说明
    - 缺少章节 → 补充内容
    - 与 wiki 不一致 → 以代码为准修正，特殊设计决策标注原因
    - 术语不统一 → 统一术语
    - 验收标准模糊 → 重写为可度量标准

    修正后重新自检修改项，直到所有 agent 可修复的问题都已处理。

    ## 输出

    按 `assets/spec-review-template.md` 模板输出 review 结果到 `docs/specs/<YYYY-MM-dd>-<name>/spec-review.md`。

    ### 遗留问题标记

    对于 agent 无法自行判断的问题，记录到「遗留问题」表中，格式：

    | 编号 | 问题 | 建议 | 状态 |
    |------|------|------|------|
    | H-01 | <问题描述> | <agent 建议> | 待确认 |

    典型需要人工确认的问题：
    - 需求优先级排序（P0/P1/P2）
    - 产品策略相关的设计选择
    - 需要外部协调的依赖问题

    ## 完成标志

    - spec.md 中所有可自动修复的问题已修正
    - spec-review.md 已写入
    - 如有遗留问题，已清晰罗列
```

## 主 agent 后续操作

Subagent 完成后，主 agent 读取 `spec-review.md`，判断：

1. **无遗留问题** → 告知用户 review 完成，调用 `workflow.py advance` 推进到 spec-human-review
2. **有遗留问题** → 向用户展示遗留问题列表，等待用户回复后继续修复循环，再次派发 subagent
