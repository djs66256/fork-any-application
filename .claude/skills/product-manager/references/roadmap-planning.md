# 路线规划

## 概述

路线规划是 product-manager 的核心决策能力。当用户提出新的功能想法或需要明确下一步方向时，执行路线规划分析，综合以下信息源给出优先级建议。

## 信息收集

分析前必须读取以下信息源（按优先级排列）：

### 必读信息源

1. **竞品调研**：`docs/product_research/` 中与目标功能模块相关的竞品文档
   - 竞品做了什么、怎么做的
   - 我们缺少哪些竞品已有的关键功能

2. **现有 wiki**：通过 `Skill("llm-wiki")` 查阅相关功能域文档
   - 当前项目已有哪些能力
   - 目标功能与现有功能的关联和潜在冲突

3. **当前进展**：`docs/product_manager/progress.md` 和 `backlog.md`
   - 哪些功能正在构建中
   - backlog 中已有的待办项

4. **现有路线图**：`docs/product_manager/roadmap.md`
   - 当前产品所处的阶段和目标
   - 主题域演进路线

5. **用户输入**：用户本次提出的想法、约束、优先级偏好

### 可选信息源

- `docs/product_manager/decisions/` — 历史决策记录，避免重复分析
- `PRODUCT.md` — 产品定位信息

## 分析流程

1. 读取所有信息源
2. 对照 `roadmap.md` 中的阶段目标和主题域规划，评估用户提出的想法属于哪个主题域、哪个优先级
3. 如用户未提出具体想法（"下一步做什么"），则扫描 `backlog.md` + 竞品差距，找出最优推进方向
4. 考虑工时约束：同一时间不应有超过 3 个 `building` 状态的迭代
5. 输出决策记录并等待用户确认

## 使用的模板

路线规划涉及以下模板，执行时按需使用：

| 用途 | 模板 |
|------|------|
| 决策记录 | `assets/decision-record-template.md` |
| 路线图更新 | 以 `docs/product_manager/roadmap.md` 现有结构为准，模板参考 `assets/roadmap-template.md` |
| 待办池更新 | 以 `docs/product_manager/backlog.md` 现有结构为准，模板参考 `assets/backlog-template.md` |

## 输出

### 决策记录

每次分析输出一份决策记录，使用模板 `assets/decision-record-template.md`，保存到 `docs/product_manager/decisions/YYYY-MM-DD-<topic>.md`。

关键字段：
- 候选方向表：编号 / 功能 / 所属主题域 / 竞品差距 / 工时估算 / 综合建议
- 建议优先级：P0/P1/P2/暂不推进，各附简要理由
- 决策：用户确认的最终决定

### 更新文档

分析完成后，更新：
- `backlog.md`：新增/调整功能项优先级
- `roadmap.md`：如有主题域路线变化

## 用户确认

路线规划分析完成后，向用户呈现建议摘要并等待确认：

> 「📊 基于竞品分析、现有 wiki 和当前路线图，建议按以下优先级推进：」
> 「1️⃣ P0：<功能名> — <简要理由>」
> 「2️⃣ P1：<功能名> — <简要理由>」
> 「…」
> 「是否按此优先级推进？或你有其他考虑？」

不代替用户做最终决策——路线规划的产出是「建议」，最终决策权在用户。
