# 竞品采集产物分析指南

采集完成后，对产物进行多模态分析，产出结构化分析文档。

## 执行流程

1. 读取 plan.md，了解采集目标、操作序列和采集阶段回填的观察记录
2. 浏览同目录 `assets/` 下的所有截图和录屏文件
3. 按「分析维度」逐项分析
4. 按 `assets/analysis-template.md` 模板输出 `analysis.md` 到 `.captures/<日期>-<name>/analysis.md`
5. 自检后更新 Task 状态

## 分析维度

根据采集内容覆盖以下适用维度：

| 维度 | 聚焦点 | 适用条件 |
|------|--------|---------|
| **交互流程** | 页面跳转关系、返回逻辑、手势响应、转场动画 | 所有采集 |
| **UI 布局详解** | 组件层级、间距、字号、颜色、图标、各元素尺寸估算 | 所有采集 |
| **加载策略** | 骨架屏、loading、分页、预加载、首屏渲染时序 | Feed / 列表类 |
| **内容策略** | 推荐逻辑可观测部分、内容组织形式、信息架构 | Feed / 首页 |
| **状态管理** | 空状态、网络错误、登录过期 | 仅当采集覆盖了这些场景 |

> 根据本次采集的实际范围选取适用的维度，不强制全部覆盖。

## 分析规范

- 逐步骤对应采集文档中的操作序列，每步操作在分析中都有对应的响应分析
- 每张截图都有对应的分析引用，引用路径为 `assets/xxx.png`
- 严格区分「事实观察」和「主观推断」：推断类结论标注 `[推断]`
- UI 描述数值化（dp、sp、颜色值等），精确值直接写数字，估算值加「约」前缀
- 无法从截图/录屏中明确识别的信息标注「不可观测」
- 不适用当前采集的维度章节标注「本次不适用」，不要删除

## 自检清单

分析文档写完后，逐项自检：

- [ ] 分析维度是否覆盖了本次采集适用的所有维度
- [ ] 每张截图是否都有对应的分析引用
- [ ] 是否区分了「事实观察」和「主观推断」（`[推断]` 标记）
- [ ] UI 描述是否数值化（dp、sp、颜色值等）
- [ ] 所有截图引用路径是否正确（相对路径 `assets/xxx.png`）
- [ ] 不适用章节是否标注了「本次不适用」而非删除
- [ ] analysis.md 文件是否已成功写入

发现问题直接修正。
