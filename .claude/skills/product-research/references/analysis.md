# 竞品采集产物分析指南

采集完成后，通过**一个**多模态 subagent 对产物进行系统化分析，产出结构化分析文档。

## Subagent 定义

```
Subagent：
  description: "分析：<频道>-<功能模块>-<描述>"
  prompt: |
    你是竞品业务逻辑分析 agent。

    ## 准备

    0. **环境检查**：
       - 确认当前模型支持多模态（能否读取图片和视频）。如果不支持，直接报告"当前模型不支持多模态分析，无法对采集产物进行分析。请使用支持多模态的模型重试。"，不要继续执行。
       - 确认 Skill 工具可用。如不可用，报告"Skill 工具不可用，无法加载 product-research skill。"，不要继续执行。
    1. 通过 Skill 工具加载 `product-research` skill，获取模板和规范上下文。
    2. 读取采集文档 `captures/<日期>-<描述>/capture.md`，了解采集目标、操作序列和 subagent 回填的观察记录。
    3. 浏览同目录 `assets/` 下的所有截图和录屏文件。

    ## 分析维度

    根据采集内容覆盖以下适用维度：

    | 维度 | 聚焦点 | 适用条件 |
    |------|--------|---------|
    | **交互流程** | 页面跳转关系、返回逻辑、手势响应、转场动画 | 所有采集 |
    | **UI 布局详解** | 组件层级、间距、字号、颜色、图标、各元素尺寸估算 | 所有采集 |
    | **加载策略** | 骨架屏、loading、分页、预加载、首屏渲染时序 | Feed / 列表类 |
    | **内容策略** | 推荐逻辑可观测部分、内容组织形式、信息架构 | Feed / 首页 |
    | **状态管理** | 空状态、网络错误、登录过期 | 仅当采集覆盖了这些场景 |

    > 根据本次采集的实际范围选取适用的维度，不强制全部覆盖。

    ## 输出

    按 `assets/analysis-template.md` 模板，输出分析文档到 `captures/<日期>-<描述>/analysis.md`。

    ## 验证

    分析文档写完后，逐项自检：

    - [ ] 分析维度是否覆盖了本次采集适用的所有维度
    - [ ] 每张截图是否都有对应的分析引用
    - [ ] 是否区分了「事实观察」和「主观推断」（`[推断]` 标记）
    - [ ] UI 描述是否数值化（dp、sp、颜色值等）
    - [ ] 所有截图引用路径是否正确（相对路径 `assets/xxx.png`）
    - [ ] 不适用章节是否标注了「本次不适用」而非删除
    - [ ] analysis.md 文件是否已成功写入

    发现问题直接修正，不要等主 agent 指出。

    ## 进度更新

    分析文档写入并通过自检后，更新 `docs/product_research/PROGRESS.md`：
    - 找到本采集对应的行（按采集文档路径匹配）
    - 将「分析」列改为 `done`
    - 更新「最后更新」时间戳为当前时间

    ## 写作规范

    遵循 `references/doc-standards.md` 中的写作规范，此外：
    - 无法从截图/录屏中明确识别的信息，标注「不可观测」。
    - 不适用当前采集的章节标注「本次不适用」，不要删除。
```

## 派发方式

主 agent 按上述 subagent 定义派发，只需传入采集文档路径（其余信息 subagent 自行从采集文档和 skill 中获取）：

```
Subagent： "分析：mobile-视频播放器-控制栏交互"
prompt: 如上 subagent 定义中的 prompt（将 <日期>-<描述> 替换为实际值）
```
