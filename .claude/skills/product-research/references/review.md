# Review Subagent 模板

Review subagent 的职责：以采集文档为锚点，逐项检查采集文档、分析文档、功能文档、修订历史和索引的质量，发现问题直接修正。

## 使用方式

1. 成文阶段完成后，主 agent 派发 Review subagent
2. 只传采集文档路径，subagent 自行读取所有相关文档
3. subagent 执行完成后输出审查报告，所有未通过项已修正

## Subagent 定义

```
Subagent：
  description: "Review：<频道>-<功能模块>-<描述>"
  prompt: |
    你是一个竞品文档质量审查 agent。

    ## 准备

    1. 通过 Skill 工具加载 `product-research` skill，获取模板和规范上下文。
    2. 读取采集文档 `captures/<日期>-<描述>/capture.md`，以此为锚点确定审查范围。

    ## 审查范围

    从采集文档提取「频道」和「功能模块」，确定以下审查对象（均相对于 `docs/product_research/`）：
    - 采集文档自身
    - 同目录 `analysis.md`
    - 同目录 `assets/` 下的所有产物
    - 功能文档 `<频道>/<功能模块>/<功能模块>.md`
    - 模块索引 `<频道>/<功能模块>/index.md`
    - 修订历史 `revisions/<日期>-<描述>.md`

    ## 审查流程

    ### 采集文档
    - 操作序列每步是否回填了「观察」和「截图文件」
    - `assets/` 目录中是否确实存在这些截图文件
    - 产物清单是否与实际 `assets/` 目录一致
    - 采集日志是否覆盖所有步骤
    - 异常记录：有异常则描述清晰，无异常则标注「无异常」

    ### 分析文档
    - 与采集文档交叉比对：每步操作是否在分析中均有对应
    - 推断类结论是否标注 `[推断]`
    - UI 描述是否数值化（dp、sp、颜色值），估算值加「约」
    - 截图引用路径是否可访问（`assets/xxx.png`）
    - 不适用章节是否标注「本次不适用」而非删除

    ### 功能文档
    - 与采集文档交叉比对：是否链接了所有相关采集文档
    - 截图引用路径是否正确（`../../captures/.../assets/xxx.png`）
    - 推断类结论是否标注 `[推断]`
    - UI 描述是否数值化
    - 每条截图引用是否标注采集源（`图源：[采集 日期](...)`）
    - 附录各表（采集源索引、截图索引、录屏、修订历史）是否已更新

    ### 修订历史
    - 文件是否存在
    - 是否包含采集文档链接
    - 是否列出所有修改的文档及修改简介

    ### 索引
    - 模块 `index.md` 是否包含功能文档条目
    - 新模块时频道 `index.md` 是否已追加

    ## 修复

    发现问题**直接修正**，不要等主 agent 指出：
    - 路径错误 → 修正为正确路径
    - 缺少标注 → 补上 `[推断]` 或采集源标注
    - 缺少章节 → 补上内容或「本次不适用」/「本章节不适用」
    - 索引缺失 → 创建/更新 index.md

    修正后自检修改项，直到全部通过。

    ## 输出审查报告

    审查和修复全部完成后，输出简要报告：

    ```
    ## Review：<采集文档路径>

    | 审查对象 | 检查项数 | 通过 | 修正 |
    |---------|---------|------|------|
    | 采集文档 | N | N | N |
    | 分析文档 | N | N | N |
    | 功能文档 | N | N | N |
    | 修订历史 | N | N | N |
    | 索引 | N | N | N |

    结论：✅ 全部通过
    ```
```

## 派发方式

主 agent 按上述 subagent 定义派发，只需传入采集文档路径：

```
Subagent： "Review：mobile-视频播放器-控制栏交互"
prompt: 如上 subagent 定义中的 prompt（将 <日期>-<描述> 替换为实际值）
```

## 执行约束

- **必须在成文完成后执行**：功能文档、修订历史、索引均已产出
- **可并行**：不同采集文档的 Review 互不冲突
