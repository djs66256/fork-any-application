# 竞品分析规划指南

在每轮迭代开始前，通过本指南确定下一轮要分析的单一路径。

## 0. 读取已有进度

读取目标频道的 `docs/product_research/<频道>/PROGRESS.md`。

1. 如 PROGRESS.md 不存在（首次使用），按以下方式初始化：
   - 从用户输入提取竞品名称、频道、目标页面
   - 按 `assets/progress-template.md` 模板创建 PROGRESS.md
   - 将用户指定的页面路径写入第一行，「路径来源」标注为「入口」，「采集完成」标注为 `⬜`
   - 创建目标页面的 `.captures/` 目录结构
2. 如 PROGRESS.md 已存在：
   - 从上至下扫描，找到第一个「采集完成」为 `⬜` 的路径
   - 该路径即为本轮采集目标
   - 向用户呈现已有进度概览（已完成数/总数）
3. 对于状态为 `🔄` 的路径，向用户确认是否为上次会话中断遗留，决定重采或继续。
4. 如所有路径均为 `✅`，提示用户："频道所有路径已采集完成，是否需要指定新入口继续？"

## 1. 确认分析范围

从用户描述中提取以下要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| 目标竞品 | 要分析哪个应用 | 见 PRODUCT.md |
| 功能模块 | 针对哪个页面/场景 | 首页 Feed、播放器、搜索 |
| 分析深度 | 覆盖的维度 | 首屏快照 / 交互流程 / 异常边界 |
| 目标平台 | mobile / web | mobile（默认） |

分析深度层次：

| 层次 | 覆盖内容 | 适用场景 |
|------|---------|---------|
| **首屏快照** | 单页面截图 + UI 描述 | 快速了解某个页面的布局 |
| **交互流程** | 完整操作链路 + 页面跳转关系 | 理解核心功能的使用方式 |
| **异常边界** | 空状态、错误处理、网络异常、登录过期 | 覆盖产品健壮性 |

如用户未明确说明深度，默认按「交互流程」执行。

**信息不足时先反问**：如用户只说"分析竞品"而未指定具体竞品、功能模块或深度，先反问澄清，不要直接进入规划。

## 2. 拆分单条路径

竞品分析是迭代式的，**每次只分析一条操作路径**。

### 拆分原则

- 一条路径 = 一个明确的起点 → 一条连续操作链路 → 一个终点
- 单路径步骤数控制在 5-8 步以内，步骤过多说明路径不够聚焦
- 路径有明确边界，能说清楚从哪个页面/状态开始、经过哪些操作、到哪个页面/状态结束

### 示例

```
播放器模块（不一次性全部拆分，每轮只选一条）：
  ├── 从首页点击视频卡片 → 进入播放器
  ├── 播放页 UI 首屏布局
  ├── 控制栏交互（唤出/隐藏、暂停/播放、进度、倍速）
  ├── 竖屏 → 横屏 → 竖屏切换
  └── 播放器退出回到首页
```

> 5 条路径对应 5 轮迭代，每轮独立采集→分析→成文→验收。

PROGRESS.md 最初只有用户指定的入口路径。后续路径在每轮验收阶段由采集中发现的交互入口追加。

## 3. 制定采集方案

对选定的单条路径，明确：

| 要素 | 说明 |
|------|------|
| **操作序列** | 从哪个页面开始，按什么顺序操作，到哪个状态结束 |
| **截图时机** | 每步后截图？仅关键帧？需要标注什么？ |
| **录屏需求** | 动画、转场、加载过渡类操作必须录屏 |
| **预计耗时** | 粗略估计 |

### 判断是否需要录屏

| 场景 | 是否需要录屏 |
|------|------------|
| 静态页面/布局 | ❌ 截图即可 |
| 页面转场动画 | ✅ 必须录屏 |
| 滚动/滑动行为 | ✅ 必须录屏 |
| Loading → 内容过渡 | ✅ 必须录屏 |
| 按钮点击反馈 | 可选，截图通常够用 |

## 4. 预制 plan.md

按 `assets/plan-template.md` 模板预制采集规划文档，保存到：
```
docs/product_research/<频道>/<页面或功能>/.captures/<YYYY-MM-DD>-<name>/plan.md
```

模板中已定义了全部字段和格式，规划阶段填写采集信息表和操作序列的「操作」「命令」「截图」「观察要点」，其余回填区（观察、截图文件、采集日志、产物清单、异常记录、执行状态）留空待采集阶段填写。

## 5. 创建 Task 并更新进度

1. 使用 TaskCreate 创建 5 个 Task 追踪本轮进度：
   - 采集：<页面> — <描述>
   - 分析：<页面> — <描述>
   - 成文：<页面> — <描述>
   - 验收：<页面> — <描述>
   - 下一轮规划
2. 将第一个 Task（采集）标记为 `in_progress`
3. 更新 PROGRESS.md 中对应路径的「采集完成」为 `🔄`

## 6. 呈现并确认

向用户呈现本轮采集计划：

```markdown
## 本轮采集计划

- **竞品**：{{名称}}
- **路径**：{{页面路径}}
- **平台**：{{频道}}
- **分析深度**：{{层次}}
- **plan.md**：`<页面>/.captures/<YYYY-MM-DD>-<name>/plan.md`
- **步骤数**：N 步 | **录屏**：是/否

### PROGRESS.md 进度

已完成：N 条 | 进行中：1 条 | 待采集：M 条

确认后开始采集。
```

用户确认后进入采集阶段。
