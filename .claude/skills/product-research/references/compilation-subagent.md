# 成文 Subagent 模板

成文 subagent 的职责：读取采集文档和分析文档，将分析结果合并到功能文档中，更新各级索引，记录修订历史。

## 使用方式

1. 采集和分析阶段完成后，主 agent 派发成文 subagent
2. 只传采集文档路径，subagent 自行读取采集文档、分析文档、功能文档和模板
3. subagent 执行完成后，功能文档已增量更新、索引已刷新、修订历史已创建

## Subagent 定义

```
Subagent：
  description: "成文：<频道>-<功能模块>-<描述>"
  prompt: |
    你是一个竞品文档工程 agent。负责将采集和分析结果合并为结构化的功能文档。

    ## 准备

    0. **环境检查**：确认 Skill 工具可用。如不可用，报告"Skill 工具不可用，无法加载 product-research skill。"，不要继续执行。
    1. 通过 Skill 工具加载 `product-research` skill，获取模板和规范上下文。
    2. 读取采集文档 `captures/<日期>-<描述>/capture.md`，提取采集信息（目标竞品、频道、功能模块、采集范围等）。
    3. 读取同目录的分析文档 `analysis.md`，获取结构化分析结果。

    ## 执行流程

    ### 1. 确定目标路径

    所有文档操作路径均相对于项目根目录下的 `docs/product_research/`。

    从采集文档的「采集信息」表中提取「频道」和「功能模块」，确定以下路径：

    - 功能文档：`<频道>/<功能模块>/<功能模块>.md`
    - 模块索引：`<频道>/<功能模块>/index.md`
    - 频道索引：`<频道>/index.md`

    ### 2. 合并到功能文档

    - 如功能文档已存在，读取当前内容后增量更新
    - 如不存在，按 `assets/doc-template.md` 模板创建
    - 分析文档与功能文档的章节名已对齐，直接按同名章节合并：
      - `## 交互流程` — 追加步骤、更新跳转图
      - `## UI 布局详解` — 追加页面、更新组件表
      - `## 业务逻辑分析` — 将子章节（加载策略、内容策略、状态管理）合并到功能文档同名子章节下
      - `## 关键发现` — 合并去重，保留非重复发现
    - 功能文档独有的章节（功能概览、与自身产品对比等）保留不动

    - 更新「基本信息」表中的「最后更新」日期和「采集源」计数
    - 更新「附录 A. 采集源索引」，追加本次采集条目
    - 更新「附录 B. 截图索引」，追加本次采集的所有截图
    - 更新「附录 C. 录屏」，追加本次录屏（如有）
    - 更新「附录 D. 修订历史」，追加本次修订条目
    - 更新「待深入」表：如本次分析发现新的待覆盖点则追加，如本次已覆盖某条目则将其状态改为"已覆盖"

    ### 3. 更新索引

    - 模块 `index.md`：如为新模块则创建，追加功能文档条目
    - 频道 `index.md`：如为新模块则追加模块条目

    ### 4. 记录修订历史

    创建 `docs/product_research/revisions/<YYYY-MM-DD>-<描述>.md`，内容包含：
    - 采集文档链接
    - 所有被修改文件的列表和修改简介

    ## 截图引用规范

    每条截图引用必须标注采集源：

    ```markdown
    ![截图说明](../../captures/<日期>-<描述>/assets/<文件名>.png)
    *图：<说明> | 图源：[采集 <日期>](../../captures/<日期>-<描述>/capture.md)*
    ```

    ## 写作规范

    遵循 `references/doc-standards.md` 中的写作规范，此外：
    - 不适用当前功能文档的章节标注「本章节不适用」，不要删除
    - 增量更新时保留已有内容，仅追加/修订相关章节，不覆盖已有的采集源引用

    ## 完成标志

    - 功能文档已更新或创建
    - 模块和频道索引已更新
    - 修订历史已创建
    - 所有截图引用路径正确且标注了采集源
```

## 派发方式

主 agent 按上述 subagent 定义派发，只需传入采集文档路径（其余信息 subagent 自行从采集文档和 skill 中获取）：

```
Subagent： "成文：mobile-视频播放器-控制栏交互"
prompt: 如上 subagent 定义中的 prompt（将 <日期>-<描述> 替换为实际值）
```

## 执行约束

- **同模块必须串行**：多个采集对应同一功能模块时，成文 subagent 必须逐个串行执行，避免功能文档写入冲突
- **不同模块可并行**：不同功能模块的成文 subagent 可并发执行，互不冲突
- 每个成文 subagent 只处理一次采集的合并，不跨采集
