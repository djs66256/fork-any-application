# 分析记录 — homepage-feed/menu-panel/recently-viewed/first-card

## 页面判定

- 代表卡片入口来自菜单抽屉“最近在看”模块中的第一张卡，标题为“我的好女媳”，进度为“2集/3集”。
- 有效点击后进入的是竖屏剧集播放承接页，而不是详情页、登录页或抽屉内展开态。
- 目标页顶部明确显示“第2集”，说明 recently-viewed 入口会把用户直接带回最近观看到的集数位置。

## 与 full-watch 的关系

### 相同点
- 两者都进入竖屏播放器语境。
- 顶部都提供返回、当前集数、倍速、更多操作。
- 页面右侧都存在互动操作列，底部都存在选集能力。
- 都是从首页相关入口直接跳入播放链路，没有中间详情页阻断。

### 不同点
- `full-watch` 文档样本强调“观看完整短剧/漫剧”的整剧播放承接，底部文案突出“观看完整短剧 全X集”。
- `recently-viewed/first-card` 更强调“继续看”，当前截图直接落在“第2集”，且抽屉来源明确是用户历史续播记录。
- `recently-viewed` 入口在业务语义上属于菜单抽屉中的续播恢复，而 `full-watch` 属于首页 Feed 单条内容的整剧转化入口。

## 去重结论

- **不应将 `recently-viewed/first-card` 直接并入 `homepage-feed/full-watch/`。**
- 原因不是页面外观完全不同，而是**入口语义、承接任务与回退上下文不同**：
  - `full-watch`：从首页卡片底部 CTA 进入整剧播放。
  - `recently-viewed/first-card`：从菜单抽屉中的续播记录进入上次观看位置。
  - `recently-viewed/first-card` 返回后回到菜单抽屉，这一上下文绑定在既有 `full-watch` 文档中不存在。
- 因此应保留为 `recently-viewed` 下的代表性子路径，用来说明抽屉续播入口的真实下钻行为；其余第二、第三张卡片仍视为同构，不再拆分。

## 关键观察

1. 第一次点击失败并非业务无跳转，而是坐标命中错误；entry XML 显示第一张卡真实 bounds 为 `[64,651][253,1041]`，第一次 `tap 160 540` 在卡片上方空白区。
2. 第二次 `tap 160 800` 成功进入播放页，证明续播卡确实是可点击深链入口。
3. 有效目标页截图中可见：
   - 顶部：返回、`第2集`、倍速、更多
   - 右侧：收藏、评论、点赞、分享
   - 底部：`选集`、`相关推荐`
   - 主内容标题：`我的好女媳`
4. 返回截图显示抽屉仍在，说明播放页关闭后会回到菜单抽屉，而不是首页首屏。

## 新增路径判断

- 当前样本未暴露新的非同构下游页面；`选集` 与 `相关推荐` 已可视，但它们属于播放页内部能力，且 `full-watch/` 下已存在 `episode-selector/` 与 `playback-options/` 代表路径。
- 因本轮目标是确认 recently-viewed 的代表卡片承接关系，不额外新增下游路径。
