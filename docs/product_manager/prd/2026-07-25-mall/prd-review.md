## 阻塞问题

### B-01：缺少 mermaid 流程图（完整性）

- **位置**：prd.md 第 4 节「核心流程」
- **问题**：仅一行文字描述「用户从底部导航进入商城 Tab → 浏览商品 Feed → 点击商品（已登录跳转详情占位/未登录跳转登录）」，缺少 mermaid 流程图。作为对比，同 Sprint 的剧场频道 PRD 有完整的 `flowchart TD` 图，底部导航 PRD 每个用户故事都有独立的流程图。
- **修正方案**：
  1. 为商城主流程添加 mermaid flowchart，覆盖：进入商城 → 浏览 Feed → 上拉加载更多 → 点击商品卡（已登录/未登录分支）→ 点击搜索框 → 点击购物车 → 点击快捷入口
  2. 同时为 US-03（登录拦截）单独补充分支流程图，覆盖匿名点击 → 拦截弹层 → 登录成功/失败/关闭弹层

### B-02：缺少目标用户角色定义（完整性）

- **位置**：prd.md 第 1 节
- **问题**：缺少「1.2 目标用户」章节。底层导航、剧场频道、搜索发现 PRD 均有此章节，但商城 PRD 缺失。用户角色定义影响用户故事的覆盖完整性和优先级判断。
- **修正方案**：
  1. 新增「1.2 目标用户」章节，至少定义以下角色（参考竞品调研 mall.md 的关键发现）：
     - **浏览型用户**：随便逛逛商品 Feed，核心需求是浏览商品卡（标题+图片+价格）
     - **主动搜索用户**：通过搜索框找特定商品
     - **权益用户**：通过快捷入口查看订单/券/钱包
  2. 为每个角色标注核心需求和对应的用户故事编号

### B-03：商品点击行为对已登录用户未定义（完整性）

- **位置**：prd.md 第 3 节用户故事 + 第 4 节核心流程
- **问题**：US-03 仅定义了匿名用户点击商品卡 → 登录拦截。但已登录用户点击商品卡后发生什么完全没有说明。核心流程中提到「已登录跳转详情占位」，但：
  - 「详情占位」是什么？是一个 toast？一个占位页面？还是跳转到 `/product/:id` 占位路由？
  - 产品调研中竞品是登录后进入商品详情/直播详情，但 PRD 将商品详情页列为「范围外」
  - 已登录用户的商品点击行为是 P0（在核心流程中）但没有对应的用户故事
- **修正方案**：
  1. 新增 US-04：「已登录用户点击商品卡」→ 跳转到商品详情占位页 `/product/:id`（仅展示商品标题+图片+价格，标注"详情页开发中"）
  2. 或将已登录商品点击行为移出范围（在范围定义中补充：「已登录用户点击商品卡 → 暂做 Toast 提示"详情页即将上线"」）
  3. 无论选哪个方案，都必须在用户故事中体现，不能只在流程图文字中提到

### B-04：商品数据模型未定义（可落地性）

- **位置**：subtasks.md ST-01
- **问题**：ST-01 提到 API 返回「标题/图片/价格/直播标记」，但未定义 Product 数据实体的完整字段和 Schema。当前 wiki 中仅有 Drama/Episode/UserProfile 三个数据模型，无 Product 模型。后端开发需要知道：字段名、类型、约束（必填/可选/nullable）、与现有模型的关联关系。此外，「直播标记」字段与 PRD 将「直播带货」列为范围外存在矛盾。
- **修正方案**：
  1. 在 PRD 中新增「数据模型」章节（或附录），定义 Product 最少字段：`id`, `title`, `cover_url`, `price`（原始价+优惠价）, `sales_count`（可选）, `created_at`
  2. 如果直播标记暂不需要，从 API 字段中移除；如果需要，明确其含义（`is_live: boolean`，表示该商品关联的直播状态）并在范围定义中说明为何保留该字段
  3. 标注 Product 模型与现有 User 模型的关联（后续订单等）

### B-05：ST-03 Android 描述缺失（可落地性）

- **位置**：subtasks.md ST-03
- **问题**：Android 子任务仅有「工时：3 人日 | P0」一行，无任何功能描述。iOS 的 ST-02 有完整的描述（搜索+购物车入口、5个快捷入口、活动横幅轮播、双列商品Feed、商品点击登录拦截）。Android 开发人员无法从子任务描述中理解具体要做哪些 UI 组件。
- **修正方案**：
  1. 补全 ST-03 描述，与 ST-02 对齐：「搜索+购物车入口、5 个快捷入口、活动横幅（轮播）、双列商品 Feed、商品点击登录拦截」
  2. 同步检查同 Sprint 的剧场频道 ST-03 和赚钱中心 ST-03，它们也存在同样的 Android 描述缺失问题

### B-06：工时与 backlog 不一致（冲突检测）

- **位置**：subtasks.md 工时总览 vs backlog.md B-017
- **问题**：subtasks 总工时为 7.5 人日，但 backlog B-017 预估为 12 人日，差异达 4.5 人日（37.5%）。同时 Sprint 5 总工时 progress.md 显示 28 人日（与 subtasks 一致），但 backlog 中 Sprint 5 三个功能合计 12+12+14=38 人日。这种不一致会导致 Sprint 规划不可信。
- **修正方案**：
  1. 以 subtasks.md 的 7.5 人日为准，将 backlog B-017 从 12 人日更新为 7.5 人日，并同步更新进度文档中的备注
  2. 同时检查剧场频道（backlog 12 vs subtasks 10.5）和赚钱中心（backlog 14 vs subtasks 10）的工时差异，一并修正

## 建议

### S-01：搜索框行为未定义（完整性）

- **位置**：subtasks.md ST-02 提到「搜索+购物车入口」，prd.md 竞品参考提到「搜索框 + 搜索按钮」
- **问题**：用户点击搜索框后应发生什么？是完全复用的 PRD-04 搜索发现页？还是商城独立的商品搜索？两者的搜索范围不同（Drama vs Product），API 不同（`/api/dramas/search` vs `/api/mall/products/search`）。当前 PRD 对此无任何说明。
- **修正方案**：
  1. 如果是复用 PRD-04：在依赖和用户故事中标注「商城搜索框跳转到搜索发现页（PRD-04），搜索范围不含商品」
  2. 如果是商城独立搜索：作为独立用户故事加入，并增加 Backend 子任务 `GET /api/mall/products/search?q=xxx`
  3. 建议首版选择方案 2（独立搜索），因为商城搜索的是商品而非短剧，复用 PRD-04 语义不匹配

### S-02：购物车入口行为未定义（完整性）

- **位置**：subtasks.md ST-02 提到「购物车入口」，竞品参考 mall.md 也提及
- **问题**：点击购物车图标后应发生什么？跳转到购物车占位页？先触发登录拦截？直接提示"功能开发中"？当前无任何定义。
- **修正方案**：
  1. 在用户故事中新增一条：「匿名/已登录用户点击购物车 → 跳转购物车占位页 `/cart`（展示"购物车功能开发中"）」
  2. 或在范围定义中补充：「购物车入口为占位图标，点击触发 Toast 提示"购物车即将上线"」

### S-03：活动横幅轮播数据源未说明（完整性）

- **位置**：subtasks.md ST-02 提到「活动横幅（轮播）」，prd.md 竞品参考提到「夏日市集等活动 Banner」
- **问题**：活动横幅的数据来源未定义。是后端 API 返回（需要新增 API 端点）？还是前端硬编码的静态占位图？轮播间隔是多少？点击后行为如何？
- **修正方案**：
  1. 首版使用前端硬编码的静态占位图（3 张占位 banner，自动轮播间隔 3s）
  2. 在范围定义中标注「活动横幅首版使用静态占位图，CMS 管理后台远期迭代」
  3. 在 API 规格中可选预留 `/api/mall/banners` 端点骨架（返回空数组）

### S-04：快捷入口占位语义不明确（完整性）

- **位置**：prd.md 第 1.3 节范围定义「快速入口占位」
- **问题**：「占位」有两种理解：(a) UI 展示图标+文字但不可点击，(b) 可点击但跳转到占位页面。当前一句话带过，没有说明 5 个入口点击后的具体行为。另外，US-02 优先级为 P1，如果 P0 阶段不实现快捷入口，商城首屏的 UI 完整性会受影响（顶部搜索区下方直接跳到活动横幅，中间缺少快捷入口区域导致布局空白）。
- **修正方案**：
  1. 明确占位行为：「5 个快捷入口展示图标+文字，点击弹 Toast 提示"XX 即将上线"」
  2. 考虑将 US-02 提升为 P0（至少 UI 展示为 P0），点击行为可降级为占位

### S-05：API 响应格式未定义（可落地性）

- **位置**：subtasks.md ST-01
- **问题**：API 规格只有一个路径和一句括号内字段描述，缺少：
  - 完整 Response JSON 示例
  - 分页参数格式（是否与 `/api/dramas` 一致？`page` + `pageSize`？）
  - 错误码定义
  - 种子数据生成方案（「预设 20+ 商品」没有说明数据生成策略：随机标题？价格范围？图片来源？）
- **修正方案**：
  1. 补充 Response 示例，参考现有 `/api/dramas` 的分页格式：

     ```json
     {
       "data": [
         {
           "id": "uuid",
           "title": "商品名称",
           "cover_url": "https://...",
           "price": 29.90,
           "original_price": 99.00,
           "sales_count": 1234
         }
       ],
       "pagination": { "page": 1, "page_size": 20, "total": 50, "total_pages": 3 }
     }
     ```
  2. 种子数据策略：使用 `faker.js` 或硬编码 JSON 文件生成 20+ 商品，封面图使用占位图服务（如 picsum.photos），标题从预设词库随机组合

### S-06：登录拦截方式与 PRD-08 版本差异（可落地性）

- **位置**：prd.md US-03「跳转登录页」vs 产品调研 mall.md「覆盖登录拦截弹层」
- **问题**：
  - 产品调研中，红果商城点击商品卡是在原页面上覆盖登录弹层（半屏/弹层形式），不是跳转到独立的登录页
  - PRD-08 的登录页是「全屏登录页」，两者交互模式不同
  - 如果使用弹层拦截，需要在 ST-02/ST-03 中增加登录弹层 UI 的工作量（不在 PRD-08 范围内）
  - 如果跳转登录页，则交互与竞品不一致
- **修正方案**：
  1. 建议首版采用「跳转 PRD-08 登录页」方案，降低开发成本，在用户故事中明确标注：「点击商品卡 → 跳转登录页（PRD-08）→ 登录成功后返回商城」
  2. 远期迭代时可改为弹层拦截（更接近竞品体验）
  3. 无论选哪个方案，都需要在 PRD 中明确写清楚，并在子任务中体现

### S-07：商城页优先级标注与进展文档一致性问题（可落地性）

- **位置**：prd.md 标注 Sprint 5 P1 vs progress.md 标注 P1 vs backlog B-017 标注 P2
- **问题**：backlog B-017 商城优先级标为 P2，但 PRD 和 progress.md 标为 P1。Sprint 5 中剧场/商城/赚钱的优先级关系需要统一。
- **修正方案**：统一为 P1（与 progress.md 和 PRD 一致），将 backlog B-017 优先级从 P2 改为 P1

### S-08：缺少「现有功能影响」章节（完整性）

- **位置**：prd.md 整体结构
- **问题**：底部导航 PRD、搜索发现 PRD 均有「第 6 节 现有功能影响」章节，说明该功能对现有功能的影响。但商城 PRD 缺少此章节。商城作为新频道，至少需要说明：不对现有功能产生任何影响（纯新增），以及是否需要注册 Web 端 `/mall` 路由。
- **修正方案**：新增「现有功能影响」章节，参考 PRD-01 格式，标注「商城为纯新增功能，不影响现有功能」

### S-09：Web 端角色缺失（跨端一致性）

- **位置**：prd.md 第 2 节「涉及平台」
- **问题**：底部导航 PRD-01 明确注册了 Web 端 `/mall` 路由（见 PRD-01 4.3 节），但商城 PRD 仅标注 Backend/iOS/Android，未包含 Web 端。如果 Web 端需要展示商城页，应纳入范围；如果 Web 端不需要，PRD-01 应移除此路由。
- **修正方案**：
  1. 如果 Web 端需要商城页：在「涉及平台」中增加 Web 端，增加 Web 子任务（1 人日，复用移动端 API，实现基础商品卡片网格布局）
  2. 如果 Web 端不需要：标注「Web 端不在首版商城范围内」，并通知 PRD-01 修改 `/mall` 路由为占位

### S-10：活动横幅轮播未在 PRD 用户故事中体现（跨端一致性）

- **位置**：prd.md 第 3 节 vs subtasks.md ST-02
- **问题**：subtasks 的 ST-02 明确列出了「活动横幅（轮播）」作为 UI 组成部分，但 PRD 的用户故事中没有对应条目（US-01 只提了商品 Feed，US-02 只提了快捷入口）。竞品参考和竞品调研中活动横幅是商城首屏的重要视觉组件。
- **修正方案**：新增用户故事「用户可以看到活动横幅轮播」或将其合并到 US-01 的验收标准中：「双列商品卡片列表上方展示活动横幅轮播，自动切换」
