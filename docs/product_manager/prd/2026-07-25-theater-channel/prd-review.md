## 🔴 阻塞问题

### B-01：范围定义自相矛盾 —— 子频道 Tab 的范围边界不清 ✅ 已修正

- **位置**：PRD 1.4 范围定义
- **严重程度**：🔴 阻塞
- **问题描述**：
  范围定义中同时写了两个矛盾的行：
  - 「8 个子频道 Tab 的 UI（可点击切换但不全做）」在**范围内**
  - 「其他子频道（真人/动漫/电影/有声书/小说/漫画）」在**范围外**，原因是「首版仅实现找剧 Tab」

  这两行直接矛盾：如果 8 个 Tab 的 UI 都在范围内，那 "其他子频道" 就不能同时标记为范围外。并且 US-02 说 "至少 3-4 个可用（找剧/真人/动漫/小说）"，这与"首版仅实现找剧 Tab" 又不一致。

- **修正方案**（二选一）：
  1. **方案 A（推荐）**：范围定义改为「8 个子频道 Tab UI 全部展示，但首版仅『找剧』Tab 有真实数据，其余 Tab 使用相同 API 返回占位数据（展示空状态骨架屏）」；将「其他子频道的内容实现」标记为范围外。
  2. **方案 B**：US-02 收窄为「首版仅找剧 Tab 可用，其余 Tab 灰显不可点击」；范围定义删除「8 个子频道 Tab 的 UI」行，保留原范围外描述。此方案简单但体验较差，建议方案 A。

### B-02：工时估算不一致 —— subtasks 与 backlog 差 1.5 人日 ✅ 已修正

- **位置**：subtasks.md 工时总览 vs backlog.md B-004
- **严重程度**：🔴 阻塞
- **问题描述**：
  - subtasks.md 工时合计 = **10.5 人日**（Backend 1.5 + iOS 4.5 + Android 4.5）
  - backlog.md B-004 预估 = **12 人日**
  - 差值 1.5 人日，且拆分维度不同（backlog 仅有总计，subtasks 按端拆分）

- **修正方案**：
  1. 确认工时估算依据（是从竞品复杂度推算还是经验估算），统一为同一数值
  2. 如确认 subtasks 的 10.5 人日更精确，同步更新 backlog.md B-004 为 10.5 人日
  3. 如确认 backlog 的 12 人日更合理，调整 subtasks 各端子任务工时（例如 Backend 1.5→2、iOS 4.5→5、Android 4.5→5）

### B-03：ST-03 Android 剧场频道页 UI 缺少描述 ✅ 已修正

- **位置**：subtasks.md ST-03

### B-04：「新剧」快捷入口跳转目标未定义 ✅ 已修正

- **位置**：PRD 1.1 竞品参考、3. 用户故事 US-03、4. 核心流程 UI/交互要点
- **严重程度**：🔴 阻塞
- **问题描述**：
  竞品红果剧场频道有「新剧」快捷入口，PRD 在 US-03 中描述为「新剧→新剧列表」，但：
  - 项目 backlog 中**不存在** "新剧列表" 或 "新剧" 相关 PRD
  - 搜索 PRD（PRD-04）的快捷入口也包含「新剧」，同样未定义其目标页
  - subtasks ST-04/ST-05 只写了「快捷入口跳转排行/分类/预约页」，未提及新剧

  这是一个缺失的功能定义，会直接阻塞开发。

- **修正方案**（二选一）：
  1. **方案 A**：在 backlog 中新增「新剧列表」功能项，单独 PRD 定义（如果新剧列表与排行、分类有本质差异）
  2. **方案 B（推荐）**：明确「新剧」跳转目标复用已有能力，例如跳转到排行页的预约榜 Tab（新上线内容），或按「最近更新」排序的列表。在 US-03 验收标准中写明具体路由和目标页。

### S-07：API 规格缺少响应格式定义 ✅ 已修正

- **位置**：subtasks.md ST-01
- **问题描述**：
  ST-01 仅给出了 URL 路径 `GET /api/dramas/channel?channel=xxx&page=1`，但缺少：
  - `channel` 参数的合法值枚举（即 8 个子频道对应的参数值）
  - Response body 的字段定义（封面、标题、热度、标签各自对应什么字段名）
  - 分页元数据格式（是否复用 `GET /api/dramas` 的 pagination 结构）
  - 示例 response

  与同一仓库中 `wiki/api/dramas.md` 的详细程度相比，ST-01 的描述过于简略。

- **建议**：
  在 ST-01 中补充：
  1. `channel` 参数枚举值：`find_drama`（找剧）、`real_person`（真人剧）、`anime`（漫剧）、`movie`（电影）、`audio_book`（听书）、`novel`（小说）、`comic`（漫画）、`big_screen`（大视听）
  2. Response 字段：`cover_url`（封面）、`title`（标题）、`heat`（热度值如 "2.3 万"）、`tags`（标签数组如 `["爆剧", "都市"]`）、`drama_id`（跳转播放用）
  3. 示例 response JSON
