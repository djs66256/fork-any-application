## 发现的问题及修正

### R-01：游戏中心在抽屉布局中但无对应用户故事

- **维度**：完整性
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：PRD 第 4.1 节抽屉布局顺序包括「游戏中心」，Q-01 也讨论了其占位图标和 Toast 行为，但第 3 节用户故事表中没有覆盖游戏中心的 story。用户故事应覆盖抽屉中所有可见模块。
- **建议修正**：二选一：
  - 方案 A：新增 US-06「所有用户 看到游戏中心入口 展示 4 个游戏图标占位，点击弹出 Toast『即将上线』 iOS/Android P1」
  - 方案 B：如果游戏中心决定不留，则从第 4.1 节布局顺序中删除游戏中心，并在 Q-01 中将答案改为「不保留，本期不做」

### R-02：US-03/US-05 平台标记为「全部」但 Backend 无 UI

- **维度**：跨端一致性
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：US-03「看到最近在看」和 US-05「看到消息预览」的平台列标记为「全部」，但这两个 story 描述的是用户可见的 UI 行为（展示卡片、展示摘要），Backend 端只负责提供数据 API，不存在「看到」的 UI 行为。
- **建议修正**：将 US-03 和 US-05 的「涉及平台」列从「全部」改为「iOS/Android」。Backend 的 API 工作在 ST-01 中已覆盖，不需要在 user story 层重复声明。

### R-03：backlog.md 中 B-012 重复条目且数据不一致

- **维度**：冲突检测
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：`docs/product_manager/backlog.md` 中 B-012「菜单面板」出现两次（P1 段落中的第 5 行和第 13 行），且数据与当前 PRD 不一致：
  - backlog 估工 10 人日，PRD 实际 9.5 人日
  - backlog 涉及端为 iOS/Android，PRD 实际为 Backend/iOS/Android
- **建议修正**：删除 backlog 中重复的 B-012 条目，保留一条并更新为与 PRD-07 一致的数据（9.5 人日，涉及端 Backend/iOS/Android，依赖 B-001）。

### R-04：播放历史数据模型缺失

- **维度**：可落地性
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：ST-01 需要实现 `GET /api/user/recently-viewed` 返回播放历史记录，但 wiki 数据模型（`wiki/features/data-models/index.md`）中不存在播放历史（PlayHistory / ViewingRecord）实体。现有的 `POST /api/player/stop` 虽然上报了播放进度，但当前为骨架（501），且未定义进度存储的持久化模型。不阻塞 PM 阶段评审，但 spec 阶段必须处理。
- **建议修正**：在 PRD 第 5 节「依赖」中增加一行：

  | 播放进度持久化 | 内部能力 | `POST /api/player/stop` 落库后 `GET /api/user/recently-viewed` 才有数据来源 | 🚧 PRD-03 |

### R-05：子任务间依赖关系未注明

- **维度**：可落地性
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：`subtasks.md` 未标注子任务间的依赖关系。ST-04/ST-05（汉堡菜单入口）依赖 ST-02/ST-03（抽屉 UI 组件）先完成，否则按钮无法打开抽屉。此外所有前端子任务依赖 ST-01（Backend API）提供数据。
- **建议修正**：在 subtasks.md 中新增「子任务依赖」章节：

  ```
  ## 子任务依赖

  | 子任务 | 依赖 | 说明 |
  |--------|------|------|
  | ST-04 | ST-02 | 汉堡菜单按钮需要抽屉组件已完成才能集成 |
  | ST-05 | ST-03 | 同上（Android） |
  | ST-02, ST-03 | ST-01 | 最近在看卡片需要 API 返回播放历史数据 |

  ST-01、ST-02、ST-03 可并行启动。
  ```

### R-06：痛点描述不清晰

- **维度**：完整性
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：第 1.1 节「痛点」写的是功能定义而非用户痛苦："菜单面板是红果 App 的核心个人工具聚合页，集成了登录入口、最近在看（续播卡片）、小游戏分发、常用功能（预约/下载）、消息预览等模块。" 这句话描述的是**菜单面板是什么**（功能定义），而不是**用户缺少它时的痛苦**。应把痛点聚焦在用户视角。
- **建议修正**：将痛点改为：

  > - **痛点**：用户缺少统一的个人中心入口。想看续播进度时不知去哪找；想查看预约/下载状态时没有快捷途径；作为新用户想登录却没有明确的引导入口。所有个人相关操作分散在各处，缺少聚合容器。

### R-07：范围表未覆盖游戏中心占位图标

- **维度**：完整性
- **严重程度**：🟡 建议
- **状态**：✅ 已修正
- **问题描述**：第 1.4 节范围定义表中「范围内」和「范围外」均未提及游戏中心，但 Q-01 的答案明确了「保留占位图标，点击行为暂为 Toast 提示'即将上线'」。既然有明确的交付物决策，应体现在范围表中。
- **建议修正**：在范围表中增加一行：

  | 游戏中心 4 个占位图标（点击 Toast 提示） | 游戏中心完整功能（小游戏 H5 容器等） | 远期迭代 |
