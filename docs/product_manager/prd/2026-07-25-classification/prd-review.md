## 发现的问题及修正

### R-01：用户故事角色不匹配

| 属性 | 值 |
|------|-----|
| **维度** | 完整性 |
| **严重程度** | 🟡 建议 |
| **状态** | ✅ 已修正 |

**问题描述**：US-02 的角色标注为「偏好明确用户」，但其行为「按维度浏览标签」本质上是探索型浏览行为。PRD 1.2 节定义了「探索型用户」角色但该角色没有对应的用户故事，所有 US-01~US-03 均标注为「偏好明确用户」。

**建议修正**：将 US-02 的角色从「偏好明确用户」改为「探索型用户」，使两种目标用户角色各有覆盖：
- 偏好明确用户 → US-01（按性别筛选）、US-03（点击标签搜索）
- 探索型用户 → US-02（按维度浏览标签矩阵）

### R-04：标签搜索链路缺少数据模型支撑

| 属性 | 值 |
|------|-----|
| **维度** | 可落地性 |
| **严重程度** | 🔴 阻塞 |
| **状态** | ✅ 已修正 |

**问题描述**：分类页的核心闭环是「浏览标签 → 点击标签 → 搜索该关键词」。但当前数据链路存在问题：
1. **Drama Schema**（`wiki/features/data-models/index.md`、`backend/src/lib/schemas.ts`）中仅有 `category` 字段（单个可选字符串），没有 `tags` 数组字段
2. 分类页 ST-01 返回的标签（如「战神」「逆袭」「甜宠」）与 Drama 数据之间没有关联机制
3. PRD-04 搜索 API（`GET /api/dramas/search?q=xxx`）声称搜索「标题+标签」，但标签字段不存在

这意味着：用户点击「逆袭」标签后，搜索只能匹配标题中含「逆袭」的 Drama。如果剧名不含该关键词，搜索结果为空——标签矩阵中的大部分标签实际上无法返回结果。

**建议修正**（三选一）：
- **方案 A**：在 Drama Schema 中新增 `tags: string[]` 字段（多值标签），搜索时同时匹配 tags 数组内容。需要同步扩展数据模型、种子数据、搜索 API，工时需增加约 1 人日。
- **方案 B**：搜索维度扩展为「标题 + 描述 + 分类（category）」的全文本 LIKE 搜索。标签搜索复用文本匹配，不要求 Drama 有结构化标签。优点是无需改 Schema，缺点是标签与内容的映射关系弱，搜索结果可能不精准。
- **方案 C**：在 PRD 范围定义中增加一项「不保证标签搜索有结果」，明确这是浏览型功能而非精准搜索，降低首版预期。远期再建立标签-Drama 映射关系。

推荐方案 A（数据模型支持最完整），但需评估对 PRD-04 搜索 API 和种子数据初始化的影响。

### R-05：「全部」Tab 的标签行为未定义

| 属性 | 值 |
|------|-----|
| **维度** | 完整性 |
| **严重程度** | 🟡 建议 |
| **状态** | ✅ 已修正 |

**问题描述**：PRD 描述了三层结构（性别 Tab + 维度导航 + 标签矩阵），并说明男频/女频各有不同标签集。但「全部」Tab 的标签展示逻辑未定义：是展示男频+女频的并集（去重/不去重）？还是使用独立的全量标签集？

**建议修正**：在 4.1 用户旅程中补充「全部」Tab 的说明。例如：
- 方案 A：「全部」Tab 展示男频+女频标签去重并集（如 ST-01 已预设全部标签组，则直接用该标签组）
- 方案 B：「全部」Tab 使用独立的全量标签集（与 ST-01 种子数据中「全部」组对应）

推荐方案 A（与 ST-01 设计一致，UI 展示全量）。
