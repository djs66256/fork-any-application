## 一、测试范围

### 1.1 测试目标

验证 PRD-12 剧场频道在 Backend、iOS、Android 三端的黑盒行为是否满足需求与设计约束，重点覆盖以下能力：

- 剧场频道默认进入与首屏加载
- 8 个子频道 Tab 的切换、空态与分页行为
- 搜索入口、识图占位入口、4 个快捷入口的承接路径
- 剧场卡片进入播放页的主链路
- 首屏错误、分页错误、参数校验错误、弱网/断网等异常场景
- iOS / Android 跨端行为一致性与不同设备形态兼容性

### 1.2 涉及平台

| 平台 | 是否涉及 | 说明 |
|------|---------|------|
| Backend | ✅ | 新增 `GET /api/dramas/channel` 契约、分页、校验与错误响应 |
| iOS | ✅ | theater 一级频道从占位页替换为真实剧场页 |
| Android | ✅ | theater graph 从占位页替换为真实剧场页 |
| Web | ❌ | 本期明确不交付 Web/H5 剧场频道真实实现 |

### 1.3 不测试的内容

| 内容 | 不纳入原因 |
|------|-----------|
| Web 剧场频道真实页面 | 本期范围外 |
| 识图真实上传、拍照、识别链路 | 首版仅要求本地占位反馈 |
| 非 `all` 子频道的真实运营内容正确性 | 首版设计即为空态承接 |
| 新剧真实列表与专属接口 | 本期仅复用轻量占位承接 |
| 离线缓存、下拉刷新、瀑布流复杂优化 | 需求明确不做 |
| 预约写操作本身 | 本期仅验证“预约入口一步进入预约榜”，不覆盖后续预约写接口 |

### 1.4 覆盖维度与用例分布

| 维度 | 覆盖重点 | 用例数 |
|------|----------|------|
