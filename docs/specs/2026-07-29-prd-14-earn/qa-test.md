## 一、测试范围

### 1.1 测试目标

验证 PRD-14 赚钱中心在 Backend、Web、iOS、Android 四端的黑盒行为是否满足需求与设计约束，重点覆盖以下能力：

- 底部 `earn` 一级频道从占位页切换为真实赚钱中心承接
- Native 容器加载赚钱 H5 首页并维持 `earn` tab 高亮
- 首页固定区块：收益头图、新手任务卡、连续看剧福利 7 宫格、现金任务列表
- `GET /api/earn/overview` 首屏加载、空态、错误态与重试契约
- 匿名用户点击代表性任务后，先在 H5 页内看到登录引导，再通过 **earn 专属 bridge** 请求宿主打开 Native 登录承接
- Native 通过 `earn.syncAuthState` 向 H5 同步权威登录态与 `apiAccessToken` 快照，且 H5 仅在内存态使用该 token
- 已登录用户点击代表性任务后，通过 Native 播放承接链路完成任务；只有 Native 播放承接层明确回传 `completed=true` 时，H5 才调用 `POST /api/earn/complete-task`
- 播放结果回传顺序固定为：`earn.completeTask`（仅 completed=true）→ `earn.restoreContext(reason='task-return')`
- 浏览器模式与 Native 模式在 bridge 缺失场景下的降级反馈一致且可理解

### 1.2 涉及平台

| 平台 | 是否涉及 | 说明 |
|------|---------|------|
| Backend | ✅ | 新增 `GET /api/earn/overview` 与 `POST /api/earn/complete-task`，负责赚钱首页聚合数据与代表性任务完成闭环 |
| iOS | ✅ | `earn` tab 接入 `WKWebView` 容器、earn 专属登录承接、任务播放承接与 host message 注入 |
| Android | ✅ | `earn` graph 接入 `WebView` 容器、earn 专属登录承接、任务播放承接与 host message 注入 |
| Web | ✅ | 提供 `/earn` H5 首页、earn bridge、host sync、状态机与浏览器降级反馈 |

### 1.3 不测试的内容

| 内容 | 不纳入原因 |
|------|-----------|
| 真实提现、账本、风控、防刷、清结算 | 本期仅要求“金币”受控闭环，不交付真实资金能力 |
| PRD-10 签到奖励与赚钱中心真实打通 | 首版仅展示连续看剧福利 7 宫格 UI，不做真实发奖联动 |
| 多代表性任务并发完成与复杂任务累计 | 本期只要求一个代表性任务最小闭环 |
| Browser 模式内真实打开 Native 登录页或播放器 | 浏览器模式只覆盖 H5 UI / API / 按钮降级反馈 |
| 设备/模拟器上的真实黑盒执行 | 当前仓库未提供设备/模拟器 testing skill，本会话仅产出测试文档并按 workflow 规则跳过执行 |
