## 发现的问题

### Shared 设计问题

#### 问题 S-1：播放器基础控制承载方式此前未显式收口，现已补齐

- **严重程度**：🟢 建议
- **维度**：与 Spec 一致性
- **描述**：spec 将“播放 / 暂停 / 进度显示 / 倍速控制”纳入范围，但原 shared / iOS / Android 设计对播放 / 暂停 / 进度显示是复用系统原生控件还是要求自定义控制条说明不足，容易造成实现边界偏移。现已统一补充为：首版优先复用系统原生播放器控件承载播放 / 暂停 / 进度显示，页面 overlay 只承载返回、倍速、互动与选集。
- **修复状态**：✅ 已修复
- **修复说明**：已在 `design.md`、`design-ios.md`、`design-android.md` 明确首版控制承载策略，并补入对应测试场景。

#### 问题 S-2：empty/no-resource 语义此前未完全收口，现已补齐

- **严重程度**：🟢 建议
- **维度**：边界与错误处理
- **描述**：原文档对 `drama 不存在`、`drama 存在但无剧集`、`有剧集但全不可播` 三类场景的契约划分不够明确。现已统一为：`drama 不存在 -> 404`，`drama 存在但无剧集 -> 200 + items=[]`，`有剧集但全不可播 -> 200 + items=[...]` 且端侧进入 no-resource。
- **修复状态**：✅ 已修复
- **修复说明**：已在 shared 与 backend 设计中补充边界表述，并补入 backend/iOS/Android 测试场景。

### 平台设计问题

#### 问题 android-1：Android 真实播放器依赖仍是 human review 前待确认项

- **严重程度**：🔴 阻塞
- **平台**：android
- **维度**：架构
- **描述**：Android 设计明确写明：若不新增 `androidx.media3`，则 coding 阶段很难完整交付真实视频播放；而 spec 的 P0 目标要求 Android 完整观看播放器支持真实播放、倍速、生命周期恢复。当前仓库也尚未引入 Media3 依赖，因此这是会阻塞落地的前置决策，不能延后到 coding 阶段再讨论。
- **修复状态**：⚠️ 待人工确认
- **修复说明**：已在 `design-android.md` 中将该问题显式提升为 design-human-review 前必须确认的前置决策项；但截至当前会话，尚未获得真实用户输入批准，因此后续 plan/coding 不能将 `androidx.media3` 视为已获授权依赖。

#### 问题 backend-1：Backend 环境变量设计与现有代码不一致，现已修正

- **严重程度**：🟡 关注
- **平台**：backend
- **维度**：文件变更
- **描述**：原 backend 设计曾使用与现有仓库不一致的配置命名（如端口与 Supabase 变量名），会误导实现与联调。现已对齐当前 backend 真实配置约定。
- **修复状态**：✅ 已修复
- **修复说明**：已将 `design-backend.md` 的配置章节改为当前实际使用的 `PORT=3001`、`SUPABASE_URL`、`SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY`、`REDIS_URL`，并说明 `PLAYER_HISTORY_REPOSITORY` 落地时需同步更新 `src/lib/config.ts`。
