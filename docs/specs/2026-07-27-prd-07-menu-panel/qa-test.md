## 一、测试范围

### 1.1 测试目标

验证 PRD-07 菜单面板在 Backend、iOS、Android 三端的交付范围是否满足需求文档中约定的核心用户路径，包括：首页汉堡菜单打开左侧抽屉、菜单固定信息架构、最近在看数据契约、关闭后再导航、占位承接、以及空态/错误态等关键行为。

本轮 QA 阶段未执行真实设备或模拟器黑盒点击测试；当前结论基于实现阶段已完成的自动化验证、构建结果、路由/状态机单元测试和代码审查文档汇总形成。

### 1.2 涉及平台

| 平台 | 是否涉及 | 说明 |
|------|---------|------|
| Backend | ✅ | 已新增 `GET /api/player/recently-viewed`，并完成 route / service / repository 自动化测试 |
| iOS | ✅ | 已完成菜单壳层、最近在看、占位页与导航时序实现，且 build / test 通过 |
| Android | ✅ | 已完成菜单壳层、最近在看、占位承接实现；菜单相关定向测试、assembleDebug、detekt 通过 |
| Web | ❌ | 本 PRD 明确不涉及 Web 菜单面板 |

### 1.3 不测试的内容

- Web 端菜单面板：需求范围外。
- 登录、消息、预约、下载、游戏中心的真实业务能力：本期仅要求占位承接或“即将上线”反馈。
- 真实设备 / 模拟器上的人工黑盒点击验证：当前会话未提供设备/模拟器专用 skill，因此按 feature-workflow 约定跳过设备执行，仅保留 QA 文档。
- Android 仓库全量历史用例修复：`./gradlew test` 中存在两条与本 PRD 无关的既有失败，不作为本期菜单面板阻塞项。
