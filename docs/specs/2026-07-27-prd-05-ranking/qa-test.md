## 一、测试范围

### 1.1 测试目标

验证 PRD-05 排行体系在 Backend、iOS、Android 三端的黑盒验收范围是否完整覆盖：

- 从搜索发现入口进入真实排行页；
- 默认加载“全部 + 热榜”第一页；
- 一级 Tab（全部 / 真人 / AI）与二级 Tab（热榜 / 推荐榜 / 预约榜）切换正确；
- 列表分页加载、空态、错误态与重试行为符合预期；
- 预约榜中的登录拦截、预约成功态、幂等与按钮状态符合预期；
- 点击排行项继续复用现有 `play` 路由进入播放页承接链路；
- Backend 排行与预约接口对客户端保持稳定契约。

本次阶段同时记录当前环境限制：**本会话未提供设备/模拟器黑盒操作 skill，因此无法执行真正的终端黑盒点击流程，只产出 QA 用例文档并按流程跳过设备执行步骤。**

### 1.2 涉及平台

| 平台 | 是否涉及 | 说明 |
|------|---------|------|
| Backend | ✅ | 提供 `GET /api/dramas/rankings` 与 `POST /api/dramas/:id/book` |
| iOS | ✅ | `rankingHome` 占位页已替换为真实排行页 |
| Android | ✅ | `ranking` 占位页已替换为真实排行页 |
| Web | ❌ | 本 PRD 不涉及 Web / H5 排行页 |

### 1.3 不测试的内容

- Web 排行页：本 PRD 范围外。
- 真实登录流程与手机号登录：由 PRD-08 承接，本 PRD 仅验证拦截接入点。
- 播放器真实播放能力：本 PRD 仅验收到“成功进入现有播放页承接链路”。
- 真机/模拟器手势黑盒操作：当前会话缺少设备/模拟器操作 skill，无法执行。
