## 一、测试范围

### 1.1 测试目标

验证 PRD-01 的应用壳与路由骨架是否满足以下目标：

- iOS / Android 建立 5 个一级频道的底部导航容器；
- 首页可进入播放页与详情页占位路由；
- 对外公开路由命名统一为 `play` / `detail`，Android 兼容 `player`；
- Web 补齐 `/search`、`/rankings`、`/mall` 路由骨架；
- Deeplink 在新容器下保持兼容或按设计安全降级。

本次 QA 阶段同时记录两类证据：

1. **已执行的自动化验证**：iOS build/test、Android test/assembleDebug/detekt、Web test/build/lint；
2. **未执行的设备黑盒步骤**：由于当前会话未提供设备/模拟器自动化 skill，移动端真实点击链路与手势回退类场景仅记录为“跳过”。

### 1.2 涉及平台

| 平台 | 是否涉及 | 说明 |
|------|---------|------|
| Backend | ❌ | 本需求不涉及后端能力 |
| iOS | ✅ | 已完成 build/test，真实设备/模拟器黑盒点击未自动执行 |
| Android | ✅ | 已完成 test/assembleDebug/detekt，真实设备/模拟器黑盒点击未自动执行 |
| Web | ✅ | 已完成 test/build/lint，路由骨架通过本地构建验证 |

### 1.3 不测试的内容

- 不测试真实业务内容（Feed、剧场内容、商城商品、赚钱中心、我的页真实数据），因为本期仅是导航骨架。
- 不测试后端接口、鉴权、数据一致性，因为 spec 与 design 明确本期无后端 API 变更。
- 不执行真机/模拟器自动化点击、滑动、手势回退，因为当前仓库未提供设备/模拟器测试 skill。
