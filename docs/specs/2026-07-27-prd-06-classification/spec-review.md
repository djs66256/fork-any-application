### 问题 1：分类标签搜索命中能力原先定义不足，已在本轮修正

- **严重程度**：🔴 高
- **维度**：可行性
- **描述**：初稿将“点击标签后复用搜索结果页”视为既有能力，但现有 Backend 搜索实现仅覆盖 `title + category`，不足以稳定承接分类标签搜索。
- **修复状态**：✅ 已修复
- **修复说明**：已在 `spec.md` 中明确：分类页复用既有搜索结果页路由，但 Backend `GET /api/dramas/search` 需要从 PRD-04 首版的 `title + category` 扩展到 `title + category + tags`，同时保持原分页与响应结构不变。

### 问题 2：搜索结果跳转语义与既有路由表述存在歧义，已在本轮修正

- **严重程度**：🟡 中
- **维度**：一致性
- **描述**：上游 PRD / subtasks 中存在早期 `search?q=` 风格描述，容易与当前已落地的搜索结果页 canonical 路由语义混淆。
- **修复状态**：✅ 已修复
- **修复说明**：已在 `spec.md` 中明确声明：Android 复用 `search/result?query=...`，iOS 复用 `.searchResult(query:)`，不新增 `search?q=` 或独立分类结果页路由。

### 问题 3：空标签维度展示规则原先未收敛，已在本轮修正

- **严重程度**：🟡 中
- **维度**：完整性 / 平台覆盖
- **描述**：初稿曾将“空维度隐藏或保留空态”留给客户端决定，会直接影响左侧导航数量、默认选中项和右侧锚点同步，容易造成 iOS / Android 行为分叉。
- **修复状态**：✅ 已修复
- **修复说明**：已在 `spec.md` 中统一为固定三维度始终保留；若某维度 `tags=[]`，左侧仍显示该维度，右侧对应分组展示空态，不隐藏锚点。
