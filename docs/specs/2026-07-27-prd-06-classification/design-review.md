## 发现的问题

本轮未发现阻塞进入 `design-human-review` 的遗留问题。

### 问题 1：spec 与 design 对“某个性别无标签数据”的结构约束表述曾不完全一致，已在本轮修正

- **严重程度**：🔴 高
- **维度**：数据契约完整性
- **描述**：`spec.md` 的边界场景曾写成“`dimensions=[]` 或全部 tags 为空”，而 shared / backend 设计明确要求始终返回固定三维度结构，会造成客户端左侧锚点和默认选中规则分叉。
- **修复状态**：✅ 已修复
- **修复说明**：已将 `spec.md` 收敛为：即便某个性别当前无可展示标签，Backend 仍返回固定三维度结构，仅允许各维度 `tags=[]`，不允许 `dimensions=[]`。

### 问题 2：backend 设计对 Supabase 路径的 tags 搜索闭环表述曾不够严格，已在本轮修正

- **严重程度**：🔴 高
- **维度**：代码现状可落地性
- **描述**：设计要求搜索扩展到 `title + category + tags`，但当前 Supabase 路径尚未具备真实 tags 存储与查询能力；若文档不说明条件，容易误解为 Supabase 路径已天然满足 PRD。
- **修复状态**：✅ 已修复
- **修复说明**：已在 `design-backend.md` 中明确：首版分类标签种子本身不强制要求 migration，但若 coding 阶段要让 Supabase 路径真实满足 tags 搜索闭环，则必须通过新增 migration 补齐可查询的 tags 存储结构；否则只能如实声明 mock/runtime 路径先闭环，不能把 Supabase 写成“已完整支持”。

### 问题 3：iOS 设计文档中个别实现与测试表述不够准确，已在本轮修正

- **严重程度**：🟡 中
- **维度**：路由与导航语义 / 测试覆盖设计
- **描述**：iOS 设计文档曾把标签点击写成必然返回可用 query，且 Deeplink 示例与当前解析器不一致，测试文件状态表述也过于乐观。
- **修复状态**：✅ 已修复
- **修复说明**：已在 `design-ios.md` 中修正为：
  - 标签点击前需 `guard let query = viewModel.normalizedTagQuery(tag)`；
  - query 规范化规则明确复用当前搜索页规则（trim、非空、最大 50 字符）；
  - Deeplink 示例修正为当前解析器支持的 `djsdrama://search/result/<query>`；
  - `DramaRemoteDataSourceTests.swift` / `DramaRepositoryTests.swift` 改为按实际情况新增或新增/修改，而不是笼统写成“修改”。
