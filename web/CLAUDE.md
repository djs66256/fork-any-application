## 端说明

Web 端代码与说明统一维护在当前目录。
如无额外说明，当前目录仅承载 Web 前端相关实现，不处理移动端或后端逻辑。

## 技术约束

- 使用 TypeScript、Next.js、Zod、React Hooks。
- 页面、组件、状态逻辑与数据校验职责应尽量清晰分离。
- 数据输入输出优先使用 Zod 做结构约束与校验。
- React 逻辑优先使用 Hooks 组织，避免不必要的 class component 或分散式副作用实现。

## 架构约束

- 使用 TypeScript 开发，避免回退到无类型或弱类型实现。
- 页面层、状态层、数据访问层应尽量分层，避免在单个文件中堆叠过多职责。
- 优先保证核心业务逻辑与数据校验逻辑具备良好的可测试性。

## 测试要求

- 涉及业务逻辑、状态转换、数据校验的改动，应补充对应测试。
- 新增场景时，应同步补齐测试。
- 如某个场景暂时无法直接测试，需要先说明原因，再决定实现方式。

## 命令约定

- 当前目录尚未看到可确认的 Web 工程配置文件。
- 在未补充真实构建配置前，不要编造运行、测试、构建命令。

## 开发约定

- 仅修改 `web/` 目录下的文件。
- API 对接需遵循仓库根目录中的 RESTful 约束。
- 禁止硬编码环境地址、token、接口前缀或其他环境相关常量，应通过配置统一管理。
